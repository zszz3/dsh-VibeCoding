# Archive DeepSeek Harness Agent Notes(中文对照)

> 这是 [SKILL.md](SKILL.md) 的中文对照,供阅读方便。**英文原文是权威版本**,执行规则时以原文为准。

本 skill 在 deepseek-harness 中新增、审计、修剪、归档、恢复或审阅 Agent Note 时触发:检查每条新 note 是否存在已被取代的现行记录,按未来决策价值对已实施 note 分类,删除已不再能防止某类诱人谬误(tempting fallacy)的已否决 note,并应用冻结的 archived/{kind} 三元组与清单(manifest)规则。

## 阅读契约

在分类之前,阅读 [Agent Note 规则](../../notes/README.md)、[归档说明](../../notes/archived/AGENTS.md),以及适用的现行生命周期(lifecycle)说明。借助当前代码、配置、包文档、生成的目录、更新的 Agent Note 与入站链接,确认某条理由(rationale)是否仍在支配或约束任何东西。

## 新增 note 时检查取代关系

每一条新 Agent Note 都会触发一次有范围的审计,审查涵盖相同决策、机制或已否决方案的现行 note。在撰写新 note 的同时就完成每条完全或部分取代的归类:在同一个 PR 中归档符合条件的已实施三元组(implemented triplet),保留并交叉链接部分取代与独立有用的理由,否决过时的提案,并删除已无法防止某类看似合理(plausible)失误的已否决 note。当新 owner 吸收了每条独特主张时,适用 Agent Note 合并规则;不要把已知的匹配推迟到以后的语料审计。

## 按未来价值分类

适用以下按生命周期划分的结果:

- **已实施 — 保留活跃**:当某条 note 的理由、备选方案、负面保证、持久化/线(wire)语义、归属边界、安全规则或重新引入条件可能指导未来变更时,予以保留。长度无关紧要。
- **已实施 — 归档**:当某项已交付决策已完成、且其正文不太可能指导未来工作时,归档该 note,例如一次性的 UI 装饰、某个狭窄适配器、某个已闭环的小缺陷、已被取代的实现细节,或当前行为在他处已显而易见的流程历史。
- **提议中 — 绝不归档**:让进行中的提案保持活跃;若它不再值得推进,就以诚实理由否决它,并满足已否决生命周期格式。
- **已否决 — 仅作为护栏保留**:只有当落败的提案仍是一类诱人且有意义的失误、且该 note 解释了它为何失败时,才保留该否决。
- **已否决 — 删除**:当被否决的想法已过时、被取代、不再 plausible、或不太可能防止再次诉讼(re-litigation)时,删除整个三元组。修复或删除入站链接。

不要为了配额而归档。检查范围内每条 note,把类似的一组归入同一原则之下,对接近的 case 动用最佳判断,并为交接记录下真正 borderline(边界)的决策。

## 校准示例

这些示例设定了门槛;字数表明,规模并非判定标准。

可归档的已实施 note 例如:

- 折叠后的侧边栏控件轨道 — 533 词:已关闭、微小的 UI 行为;
- Commander 参数适配器 — 1,498 词:大量的实现细节,却几乎没有未来设计杠杆;
- documentation graph atlas — 920 词:已完成的文档图谱机制,其当前生成器是权威来源。

保留的已实施 note 例如:

- 事件溯源会话 — 248 词:基础性权威与持久性边界;
- 单一 Harness 归属解析器 — 596 词:跨产品归属规则;
- 项目会话目录 — 628 词:持久化存储与身份策略;
- 并行 pre-push 门禁 — 400 词:borderline(边界),但仍指导门禁调度与资源调优;
- 丢弃的图像内容块 — 334 词:保留到多模态支持落地,因为它阐明了协调一致的重新引入条件。

已否决 note 例如:

- 保留 折叠 compaction 包拆分 — 426 词:合并这些包的诱惑仍然有意义;
- 删除 通过工具调用流式传输工作流进度 — 972 词:其 ACP/UI 前提已过时;
- 删除 丢弃 ACP 终端元数据 — 362 词:后来的"仅自动化 ACP"决策解决了该问题。

## 归档一个已实施三元组

1. 把完整的 `foo.md`、`foo.zh.md` 与 `foo.i18n.yaml` 三元组从 `implemented/<kind>/` 移到 `archived/<kind>/`;归档路径中故意不含 `implemented`。
2. 不改动正文。只在 `Status: implemented` 正下方插入 `Archived: YYYY-MM-DD`,两个语言文件均使用归档日期,且两侧取值相同。
3. 机械地重录这两个仅改元数据的编辑所对应的 sidecar 哈希。不要翻译、重排格式、更新事实,或修复 note 内的链接。
4. 搜索现行文案中的入站链接。将它们重定向到当前权威,仅在历史快照(snapshot)被刻意引用时改为指向归档路径,否则删除。绝不校验或修复已归档 note 之外的链接。
5. 运行 `pnpm run verify-archived-agent-notes --write`。其仅追加模式先证明每个既有密封(seal)仍匹配,然后只新增三元组哈希。之后运行普通校验器。

三元组密封(seal)之后,绝不编辑、移动、翻译、重排格式或删除它。已归档 note 仍是有效的入站链接目标,但属于历史快照(snapshot),而非当前行为(behavior)的权威。

## 校验并报告

运行归档校验器的聚焦测试、`pnpm run verify-archived-agent-notes`、`pnpm run doc-sync`、`pnpm run lint` 与 `git diff --check`;通过 [dsh-pre-push-checks](../dsh-pre-push-checks/SKILL.md) 选取任何其他证据。

报告:保留的现行已实施 note、已归档的已实施 note、已保留/已删除的已否决 note、被否决的提议中 note(如有),以及每个真正 borderline 案例及其字数与选定结果。不要声称已归档的出站链接有效:归档校验器故意从不检查它们。
